## 二、判定标准

本次审查采用以下基准，所有数值可复现：

1. **对比度门槛**：WCAG 2.1 AA —— 正文 4.5:1，大字（≥18.66px 或 ≥14px 粗体）与图形/界面元件 3.0:1。
2. **基准色必须用真实卡片底**，不能用纯白。本项目明版卡片为 `#FCF7ED`、暗版卡片为 `#23222F`。这一点直接决定了 A1 与 A6 两项的判定结果。
3. **大面可辨性用 ΔL\*（CIE L\* 明度差）**，而非对比度比值——对比度是给小字号文字用的指标，判定「卡片是否浮起」应看明度差。
4. **单值控件与整组配置分开评估**——形状问题只在真实渲染尺寸下判定，不采信源码推断。

## 三、问题清单

### A 类 · 对比度不达标（6 项）

基准：明版卡片 `#FCF7ED`、暗版卡片 `#23222F`。

| 编号 | 令牌 / 场景 | 明版 | 暗版 | 门槛 | 判定 |
|---|---|---|---|---|---|
| **A1** | `ink-3` 说明文字 | **4.31** | **4.34** | 4.5 | 两版均差一口气（0.19 / 0.16） |
| **A2** | `gold` 作文字色 | **2.94** | 7.14 | 3.0 / 4.5 | 明版未达，暗版无碍 |
| **A3** | `ink-4` 被当正文使用 | 3.56 | 3.14 | — | 令牌注释限定「仅占位符/装饰/禁用」，实有 4 处正文用法 |
| **A4** | **已完成项文字** | **1.68** | **1.83** | 4.5 | **严重不可读**，本轮最重的一项 |
| **A5** | `card-done` 面差 | ΔL\* 1.1 | ΔL\* 7.0 | — | 明版「沉下去」几乎无效（见下） |
| **A6** | `ink-3` 注释基准错误 | 注释 4.6 / 实算 4.31 | — | — | 基准色错，把「差一点」判成了「达标」 |

#### A1 · `ink-3` 说明文字：两版都差一口气

`theme.css:66` 与 `:175`。这是全局「说明文字」色，用量最大，4.31 / 4.34 距门槛仅差 0.2，属于「肉眼看不出、但确实不达标」的典型。修正值复算：

| 版本 | 现值 | 建议值 | 改后 |
|---|---|---|---|
| 明 | `125 116 102` | `112 103 89` | **5.21** |
| 暗 | `138 132 150` | `152 147 166` | **5.26** |

改动量：两个数字，全局生效，不牵动任何其他令牌。（这处注释为何会误判为达标，见 A6。）

#### A2 · 明版文字金不足

`gold` 明版 `#B08C44`（`theme.css:84`）对卡片 2.94，低于图形门槛 3.0；若作为正文则距 4.5 更远。更麻烦的是三处调用还叠了透明度：

| 位置 | 写法 | 实际对比度 |
|---|---|---|
| `ChecklistItem.tsx:216` | `text-gold opacity-85` | 2.45 |
| `ChecklistGroupCard.tsx:211` | `text-gold opacity-85` | 2.45 |
| `EmptyState.tsx:85` | `text-gold opacity-85` | 2.45 |
| `CollapsibleSection.tsx:76` | `text-gold opacity-70` | 2.05 |
| `EmptyState.tsx:86`、`Tags.tsx:26` | `text-gold` | 2.94 |

**建议：文字金一律走 `gold-hi`，`gold` 只保留给描边与纹样。** 现成的 `gold-hi` 明版对卡片 **4.64**，已达标。

**不建议的做法**：直接压深 `gold` 本身。它同时管着和纸金线与底纹描边（`theme.css:297/327`），压深会把工艺层一起弄脏。

> 注：`HubCard.tsx:97` 与 `PageHead.tsx:54` 已经用的是 `gold-hi`，是正确示范——本项目内部已存在两种口径，应统一到 `gold-hi`。

#### A3 · `ink-4` 四处越界当正文

`theme.css:67` 注释明确限定 `ink-4`「仅占位符 / 装饰 / 禁用」，但实际有 4 处承担了正文或整段说明：

| 位置 | 内容 |
|---|---|
| `YuhunSection.tsx:313` | 整段表下说明（`text-2xs leading-relaxed`） |
| `YuhunSection.tsx:201` | 单元格内说明行 |
| `StatsPage.tsx:61` | 状态色分支 |
| **`ClearDataSection.tsx:123`** | **删档前的风险说明** ← 最应改的一处 |

删档是不可逆操作，其风险说明却用了全库最淡的灰（明 3.56 / 暗 3.14）。建议这 4 处提到 `ink-3`（改后明 5.21 / 暗 5.26）。

#### A4 · 已完成项文字实际对比度 1.68 / 1.83（本轮最重）

这是三级衰减相乘的结果，单看任何一级都不明显：

| 层级 | 位置 | 作用 |
|---|---|---|
| ① 卡底 | `ChecklistItem.tsx:163` `bg-card-done` | 底本身已低于普通卡 |
| ② **整卡** | `ChecklistItem.tsx:149` `opacity-60` | **整张卡连内容一起变淡** |
| ③ 文字 | `ChecklistItem.tsx:216` `text-ink-4 opacity-50` | 文字在半透明卡上再打五折 |

实测合成结果：

| 版本 | 卡底合成色 | 文字合成色 | 最终对比度 |
|---|---|---|---|
| 明 | `rgb(241,234,220)` | `rgb(190,182,166)` | **1.68** |
| 暗 | `rgb(23,22,30)` | `rgb(68,66,79)` | **1.83** |

全项目对「已完成」的表达口径是「**不消失，沉下去**」（见 `ViewBar.tsx:23`、`sort.ts:184` 注释），但 1.68 已经接近「消失」，与既定口径相悖。

**建议**：去掉第 ② 级的整卡 `opacity-60`（`ChecklistItem.tsx:149`、`ChecklistGroupCard.tsx:135`、`HubCard.tsx:68`），把第 ③ 级文字由 `ink-4@50%` 提到 `ink-3`。改后复算：

| 版本 | 对 `card-done` 底 |
|---|---|
| 明（`ink-3` 建议值） | **4.69** |
| 暗（`ink-3` 建议值） | **5.66** |

「沉下去」的语义由卡底色 + 朱红划线 + 蛇目符（`ChecklistItem.tsx:226`）三个通道承担，已足够，不需要再叠整卡透明度。

#### A5 · 明版已完成卡「沉下去」幅度不足

用 ΔL\* 衡量大面分离度：

| 版本 | 普通卡−画布 | 已完成卡−画布 | 普通卡−已完成卡 |
|---|---|---|---|
| 明 | 5.2 | **1.1** | 4.1 |
| 暗 | 10.0 | 7.0 | 3.1 |

明版 `card-done`（`#F2EBDE`）与画布（`#EFE8DA`）的 ΔL\* 仅 **1.1**——已完成卡几乎融进画布，而暗版同项是 7.0。这是明暗对照的典型失配（暗版成立、明版未成立）。

建议明版 `card-done`（`theme.css:58`）再降一档，候选复算：

| 候选值 | 对普通卡 ΔL\* | 说明 |
|---|---|---|
| `#F2EBDE`（现值） | 4.1 | 偏弱 |
| `#EDE5D5` | 6.2 | 稳妥 |
| **`#E9E0CE`** | **7.9** | **推荐**，与暗版 7.0 量级对齐 |

#### A6 · 注释里的基准色是错的（A1 的根因）

`theme.css:66` 的注释写着「说明文字：**白卡**上 4.6:1」。按纯白 `#FFFFFF` 复算确实是 **4.60**；但实际卡片是 `#FCF7ED`，复算落到 **4.31**——正好从「达标」翻转成「不达标」。

**通用教训**：令牌注释里的对比度必须标注**基准色**，且基准色要用真实面，不能默认纯白。否则注释本身会成为误判源头。

### B 类 · 形状未跟随换肤（1 项）

| 编号 | 位置 | 现状 | 判定 |
|---|---|---|---|
| **B1** | `TodayPage.tsx:77` | `rounded-t-sm border border-b-0` | 圆肩 + 直角脚 + 底边开口 |

`tailwind.config.ts:149` 中 `sm` 已由 4px 放大到 **11px**（约 3 倍）。这个写法原本是为 4px 圆角时代的「符札签」设计的，圆角放大后形状走样为「圆肩方脚的拱门」：

- 顶部是 11px 大圆肩，底部仍是直角，两侧廓形不对称
- `border-b-0` 让选中签与下方内容之间没有接缝，「接上了」的视觉语义失效
- 与同一产品内其他控件（全圆胶囊）不是同一套语言

**影响面精确可控**：全库扫描 `grep -rn "rounded-[trbl]-\|rounded-\[" src/` 仅命中这 1 处，说明是局部遗留，不是体系问题。

**建议**：今日页页签直接换用既有的 `Segmented` 组件（`components/common/Segmented.tsx`）。工具页三个子签（结界寄养/御魂/悬赏）与统计页时间范围都已采用它（全圆胶囊 + 朱红渐变实心），换过去既归位形状，也顺带消掉一处手写样式。

### C 类 · 结构一致性与版式效率（5 项）

#### C1 · 三页缺页头

`PageHead`（衬线大标题 + 全页唯一等宽倒计时）目前只用在 **今日 / 本周 / 本月 / 限时** 四页。实测各页首个 `h2` 的位置：

| 页面 | `h2` 顶部位置 | 页头 |
|---|---|---|
| 今日 | 13px | 有 |
| 本周 | 13px | 有 |
| 本月 | 13px | 有 |
| 限时 | 12px | 有 |
| 统计 | **null** | **无** |
| 工具 | **null** | **无** |
| 设置 | **null** | **无** |

`h2` 为 `null` 即该页正文中不存在二级标题，直接以日历卡 / 子签 / 分组标题顶到内容区上沿。

**建议**：补齐三页 `PageHead`。组件已支持 `countdown` 缺省（`PageHead.tsx:31`，`countdown?: string | null`），无倒计时需求的页面不传即可。顺带把有页头四页的 13px / 12px 统一到一个 padding 令牌。

#### C2 · 三页大面积空区（1440×1000 实测）

| 页面 | 内容底边 | 空区 | 占比 |
|---|---|---|---|
| 本月 | 453px | **547px** | **55%** |
| 工具 | 481px | **519px** | **52%** |
| 统计 | 593px | **407px** | **41%** |

纸纹铺满下方留白，观感偏「没写完」。本月页只有 4 张卡却仍按 2 列排，右列空一半。

#### C3 · 内容区上限偏窄，网格缺第三列断点

两处写死的上限：

| 位置 | 现状 |
|---|---|
| `DesktopShell.tsx:97` | `mx-auto max-w-5xl`（1024px） |
| `layout.ts:24` | `CHECKLIST_GRID = 'grid grid-cols-1 gap-2 px-3.5 py-2 lg:grid-cols-2'` |

1440 视口下 `main` 实测宽 1216px，内容区被钉死在 1024px，两侧各空 **96px**；1920 下空得更多。因为网格只有 `lg:grid-cols-2` 两个断点，卡片宽度被固定为约 494px×2，宽屏下无法利用余量。

**建议**：内容区上限放到 `max-w-6xl`，网格补一档 `2xl:grid-cols-3`。注意 `CHECKLIST_GRID` 的注释（`layout.ts`）里详细论证过断点选择，追加断点时应在同一处补上论证，保持该文件的决策记录完整。

#### C4 · 长文本块未被收束

实测最长文本块宽度 **1024px**（即占满内容区）：

| 页面 | 最长块宽度 | 文本量 |
|---|---|---|
| 统计 | 1024px | 330 字 |
| 工具 | 1024px | 254 字 |

12px 中文在 1024px 下约 **85 字/行**，远超舒适阅读区间（40–50 字）。**建议**给这类整段说明加 `max-w-[42em]`（约 42 字/行）。

#### C5 · 10px 小字回归

`text-2xs`（10px）全库 **17 处**。其中最需处理的是移动端御魂表：

- `YuhunSection.tsx:158`：`const cellText = variant === 'desktop' ? 'text-xs' : 'text-2xs';`
- `YuhunSection.tsx:282`：`text-2xs`（"N 种"计数）
- `YuhunSection.tsx:313`：`text-2xs leading-relaxed`（整段说明）

同一文件内已有注释记录「4 字名换行两行」的实际问题。项目此前已明确「CJK 在 10px 下笔画会糊」并将字号整档上抬，此处属回归。**建议**移动端单元格改用 `text-xs`（12px），至少提到 11px。

### E 类 · 令牌治理（1 项）

| 编号 | 令牌 | 状态 |
|---|---|---|
| **E1** | `--c-s-locked` | 定义完整，**零消费** |

证据：

- `theme.css:96`（明 `138 147 163`）、`theme.css:197`（暗 `71 85 105`）均已定义
- `tokens.ts:54` 已导出 `stateLocked`
- `tailwind.config.ts:100` 已映射为 `text-state-locked` 等类

四态令牌实际用量：

| 态 | 类使用次数 | 说明 |
|---|---|---|
| `state-active` | 11 | 正常使用 |
| `state-ready` | 1 | 仅 `ornament/index.tsx:271` 状态色映射 |

**建议**：二选一——① 删除 `--c-s-locked` 与 `stateLocked`，四态改为三态口径；② 保留但把注释改准（说明当前由金替代、令牌预留给后续）。**不要**留着现在的状态，令牌表与实现不一致会让后续维护者误以为存在第四个状态色。

## 五、明确不建议改动的部分

以下为审查中确认**做得对**或**经复算确认不是问题**的内容，改动会造成退步：

| 项 | 结论 |
|---|---|
| **暗版 `gold` 作文字** | 7.14，完全达标。**不要**为了与明版对称而调整暗版 `gold` |
| **明暗浮起方向** | 两版卡片都比画布亮，方向一致且正确 |
| **`gold-hi` 的分版方向** | 明版压深（`#8C6B22`）、暗版提亮（`#E6CD8E`），方向相反——这是明暗对照的正确做法（明版做描线感、暗版做发光感），保持 |
| **底纹强度** | 麻叶纹 `0.115`/`0.085`、点阵 `0.15`/`0.13`，落在「退一步才看见」区间，未抢戏 |
| **入场动效** | `reveal` / `pop` 只做 `transform`，`opacity` 未进关键帧——规避了「动画时间轴被冻结时元素永久停在 `opacity:0`」的致命陷阱，保持 |
| **令牌纪律** | 全库未发现 `#RRGGBB` 字面量散落，色值统一走 CSS 变量，保持 |

> **一处曾被怀疑、已排除的问题**：审查中一度怀疑存在 `#E5E7EB` 的「离板色」边框。核对后发现那是元素**未设置边框时浏览器返回的默认计算值**，并非实际样式，不属问题，未计入清单。

**① 确认 dev server 实际提供的代码**

项目源码不在默认工作目录下，且 `localhost:5173` 运行的可能不是磁盘上最先找到的副本。唯一可信来源是直接向服务器索取转译后的模块：

**② 逐页真实渲染取证**

SPA 使用内存路由（zustand `nav`），无法通过 URL 深链。需真实点击导航逐页截图，且**每个动作后必须等待**——React 状态更新是异步的，同步连点会全部打空。

```bash
node "$HOME/.workbuddy/skills/html-visual-qa/assets/cdp-live.mjs" pages \
  '{"url":"http://localhost:5173/","nav":["今日","本周","本月","限时","统计","工具","设置"],
    "viewport":{"w":1440,"h":1000,"dsf":1.5},"out":"_shots"}'
```

**③ 计算样式取证与对比度复算**

不靠肉眼判断颜色：

```bash
node "$HOME/.workbuddy/skills/html-visual-qa/assets/cdp-live.mjs" styles \
  '{"url":"http://localhost:5173/","nav":["今日"],
    "probe":"(()=>{const e=document.querySelector('main p');return{fg:getComputedStyle(e).color,bg:getComputedStyle(document.body).backgroundColor};})()"}'
```

再用 WCAG 公式（sRGB → 线性化 → 相对亮度 → 比值）复算，基准色取**该元素实际所在的卡片底色**。

**④ 排查半边圆角**

圆角档位整体放大后，为小圆角时代设计的「半边圆角」写法最易走形，一行即可扫清影响面：

```bash
cd /d/yys-checklist && grep -rn "rounded-[trbl]-\|rounded-\[" src/
```
