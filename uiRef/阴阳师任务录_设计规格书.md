# 式神委托 · 任务录 — 设计规格书

> 配套文件：`阴阳师任务录_朱印深化版.html`
> 定位：阴阳师风格的**游戏任务清单**，明暗双主题，纯 CSS + 内联 SVG 实现，零外部依赖。

---

## 0 · 一句话定位

**墨底、朱红、金箔三色，配麻叶纹与御币的"符札感"任务面板。**
浅底版不是反色，是重算色阶的另一套完整语言——两版共享同一份骨架，只有色彩与描边方向相反。

| 属性 | 暗版 | 明版 |
|---|---|---|
| 气质 | 神社符札，肃穆有仪式感 | 和纸手札，明亮可摊开 |
| 底色明暗 | 墨黑底（深） | 米白纸底（浅） |
| 强调处理 | **提亮**制造发光感 | **压深**制造描线感 |
| 卡片浮起方向 | 比底色**亮** | 比底色**暗** |
| 适用 | 夜间 / 长时段盯屏 | 日间 / 展示 / 打印 |

## 1 · 设计语言总纲（三条不可违背的铁律）

### 铁律一 · 去框
**禁止任何"方框 + 内含符号"的印章构图**（顶栏、状态标记、微标记所有位置一律不含）。
框与符号争夺同一位置，30px 内塞两层，无论怎么调透明度都还是重。
**印记只允许占一层**，三选一：
1. 纯符号 —— 五芒星 / 四芒星 / 菱形 / 同心圆环，无底板无外框
2. 纯线条 —— 朱红划除线、朱红短横
3. 纯文字/数值 —— 倒计时、计数，配 1px 金竖线分隔

### 铁律二 · 唯一高亮位
全屏只有「可提交」态可以使用高饱和色 + 金描边 + 淡色底。
「已完成」必须**主动降饱和沉下去**，而不是消失——完全不显示会让人忘了有这项，显示得太清楚又抢戏。

### 铁律三 · 明暗换算不是反色
- 暗版靠**提亮 + 低透明**做发光；明版靠**压深 + 高透明**做描线，方向相反。
- 浅底上纹样天然吃亏，明版底纹浓度要比暗版**更高**才看得见。
- 卡片"浮起方向"永远背离底色：暗底上卡片更亮，明底上卡片更暗。

## 3.5 · 和风 icon 库（12 枚，24×24 统一视野）

> **判据**：能不能在 17px 尺度上"一眼认出来"。认不出的就不是 icon，是噪点。
> 器物类**可以**做 icon（单色描边线稿），但**不能**做装饰填充色块——两者的分界就在"是否有体积感"。

全部图标规则：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="1.5"`、圆头圆角、无背景块无描边框。

| 图标 | id | 语义 / 用在哪 |
|---|---|---|
| 晴明纹（五芒星） | `i-seimei` | 封魔 · 秘闻副本、统计待提交 |
| 鸟居 | `i-torii` | 副本 / 结界 · 御魂、统计进行中、分组「日常委托」 |
| 御灵符（竖符纸） | `i-ofuda` | 悬赏封印 · 面板右缘装饰 |
| 提灯（紙灯籠） | `i-chochin` | 活动 · 分组「活动委托」、妖气封印 |
| 注连绳 + 纸垂 | `i-shimenawa` | 末组下方收束横幅（纯装饰层） |
| 团扇 | `i-sensu` | 觉醒材料 |
| 达摩 | `i-daruma` | **完成度隐喻 —— 点睛**，见 §5.3 |
| 铃（神樂鈴） | `i-suzu` | 通知 / 提醒 · 顶栏、统计已完成 |
| 折扇 | `i-ougi` | 周常 · 分组「周常委托」 |
| 五芒星（实心） | `i-star5` | 备用 |

**17px 尺度下的简化铁律**（实测得出）：
- **器官细节一律砍掉。** 达摩首版画了两只 `r=2.3` 的空心眼窝 + 嘴，在 15px 下糊成一团黑点；简化成「圆身 + 一弯嘴 + 两只实心圆眼」才立住。
- **内部纹理不超过 2 条。** 提灯首版画了 3 条横纹 + 复杂鼓身，缩到 16px 变成锯齿；减到 1 条横纹、鼓身改直边梯形才对。
- **描边统一 1.5px。** 1.4px 在小尺寸下会因抗锯齿变灰变虚；1.5px 是"既细又实"的下限。
- **线条总数 ≤ 7 条。** 折扇首版 8 条扇骨在 16px 下粘连，减到 6 条才分得开。

**判为不可用（保持原判）**：纸人 / 绘马 / 手鞠（`17px` 下完全认不出）；太极八卦（阴阳师手游里极少用且刻板）；庵点（太小看不见）；三巴纹（需 ≥14px 否则糊成一团）。

## 4 · 四态状态机

### 4.1 判定规则

```
done === true            → done     已完成
cur >= total             → ready    可提交   ← 全屏唯一高亮
cur > 0                  → active   进行中
cur === 0                → locked   未接取
```

### 4.2 视觉通道分配（四态四通道，互不抢占）

| 状态 | 左侧 3px 竖条 | 卡片底 | 任务 icon | 文字 | 底轨 | 菱形格 |
|---|---|---|---|---|---|---|
| 未接取 | `#475569` | `--card` | `--s-locked` 65% | `--ink-2`，序号 30% | 空 | 描边 60% |
| 进行中 | `#3B82F6` | `--card` | 金 85% | `--ink` | 蓝色实心段 | 蓝实心 = cur |
| **可提交** | `#F5C542` | `--card` + 淡金叠层 + 金 inset 描边 | 金 85% | `--ink` | 金色满格 | 金实心 |
| 已完成 | `#7A4A4F` | `--card-done` | `--ink-mute` 50% | `--ink-mute` + 朱红划除线 | 淡朱 | 全空心灰 40% |

### 4.3 计数与进度

- **分段格**：格数 = 目标次数，**上限 10 格**（超过就变成一排噪点，眼睛数不出来）。
- 单次任务（total=1）**不画格**，第二行退化为说明文案（"未接取 · 于结界入口领取" / "已达成 · 奖励已领取"），文案随状态联动。
- **卡片底轨**：卡底内嵌 2px 全宽轨道，实心段 = 进度比例。装饰与信息合一，等于白捡一层视觉密度。

### 4.4 图标语义分配

任务名左侧图标 = **任务类型**（不是稀有度）——类型比稀有度更有信息量。
分组头图标 = 该组的时间属性（日常→鸟居 / 周常→折扇 / 活动→提灯）。
统计卡图标 = 状态符号（进行中→鸟居 / 待提交→五芒星 / 已完成→铃）。

| 任务 | 图标 |
|---|---|
| 御魂 · 十层 | 鸟居 `i-torii` |
| 觉醒材料 · 风转轮 | 团扇 `i-sensu` |
| 悬赏封印 · 妖气 | 御灵符 `i-ofuda` |
| 秘闻副本 · 竞速 | 晴明纹 `i-seimei` |
| 妖气封印 · 集结 | 提灯 `i-chochin` |

## 5 · 交互与动效规格

| 动作 | 反馈 | 时长 / 曲线 |
|---|---|---|
| 点击卡片 | 补满进度 → 提交完成；再点取消 | 背景 300ms ease |
| 点击菱形格 | 推进到该格；点当前最亮那格则回退一格 | 格子 220ms ease |
| 完成瞬间 · 划除线 | `h3::after` 1.2px 朱红，`scaleX(0→1)` **从左往右扫** | 300ms `cubic-bezier(.2,.9,.3,1)` |
| 完成瞬间 · 蛇目纹 | 紧贴任务名右侧 10px，`opacity 0→.75` + `scale(.6→1)` | 300ms 同上 |
| 底轨增长 | 宽度过渡 | 350ms 同上 |
| 悬停卡片 | 底色 → `--panel-2`；可提交态加金晕 | 300ms ease |
| 悬停菱形格 | `scale(1.35)` | 220ms ease |
| 倒计时 | 每秒递减，等宽字体防跳动 | 1000ms |
| **达摩点睛** | 全部任务完成时：右眼 `opacity 0→1` + 整只转朱红 `--crimson` | 450ms ease |
| 全清静默 | 全清时「进行中 / 待提交」两卡数值退为 `--ink-mute`，描边退为 `--line-inner` | 300ms ease |

### 5.1 达摩点睛（本轮的"彩蛋"）

达摩不倒翁的传统玩法：**许愿时涂左眼，愿望达成时涂右眼**。
映射到任务清单上——**左眼常亮（有愿在许），右眼在全部任务完成时点亮，同时整只达摩由金转朱红**。

```
.panel.all-done .daruma .eye-r{opacity:1}      /* 右眼点亮 */
.panel.all-done .daruma{color:var(--crimson)}   /* 金 → 朱红 */
```

判定逻辑挂在 `updateStats()` 里，与统计三卡同一次刷新，不额外增加状态源：
```js
const allDone = all.length > 0 && all.every(t => t.dataset.state === 'done');
document.querySelector('.panel').classList.toggle('all-done', allDone);
```

**连带的静默处理**：全清时如果"进行中 00"还留着醒目的蓝色、待提交卡还顶着金描边，
会与"任务做完了"的语义打架。所以全清态下这两卡主动退成弱化色，
**只留「已完成」一卡有颜色**——一屏之内依然只有一个视觉重心。

| 键盘 | `Enter` / `Space` 触发卡片；`:focus-visible` 2px 金环 | — |

**动效归属原则**：印章/徽记的仪式感价值在"点击完成的瞬间"，不在"长期驻留"。静态列表里一律收敛为最轻的一笔，把仪式感全部押给转场。

> 唯一允许常驻的"仪式"是**达摩**：它常驻但极轻（17px 金 70%），只在全清那一刻发生变化；
> 而且它承载的是"状态"而非"结果"——符合"静态层只放状态、仪式交给动效"的原则。

## 6 · Tab 栏与页面结构

四个 tab：**日常 / 周常 / 活动 / 设置**。前三者是任务列表的三个分类，设置是独立页。
前三个靠左依次排列，**设置签 `margin-left:auto` 推到最右**，与前三个在空间上断开——视觉上就说明了"它不是分类，是另一个层级的页面"。

### Tab 签造型（"符纸签"）

不是常见的那种下划线 tab，而是**一片贴上去的符纸**：

| 部位 | 实现 |
|---|---|
| 签体 | `border-radius: 3px 3px 0 0`（上圆下方），选中态 `background: var(--panel-2)` + `border: 1px --line-outer`，下边框透明接入面板 |
| 底轨 | `.tabs::after` 一条 `--line-inner` 横线，把四片签串在同一条轴上 |
| 顶部朱线 | 选中签 `::before`，22×2px 朱红，居中——像符纸的"额束" |
| 底部菱形 | 选中签 `::after`，7×7px 旋转 45°、只留右下两边描边，嵌在底轨上做节点 |
| 内容 | icon(15px) + 名称（衬线 12.5px / 字距 .16em） + 计数 pill（mono 9.5px） |
| 设置签 | 无计数 pill（它不是分类，没有"数量"语义）；选中时顶部朱线改金色 `--gold-hi` |

### 面板切换

`display` 驱动可见性，**动效只做 translateY(5px) 位移**，详见 §9 陷阱七。

## 7 · 设置页（纯视觉稿）

**明确声明为静态展示**：分组头右上角带一个虚线描边的「静态」pill，页脚另有一行——
> 「本页仅为视觉稿 · 所有控件为静态展示，不承载交互」

这一句是必要的：拿到图的人第一反应是"点一下试试"，不写清楚就会被当成功能缺失。

### 三段式分组（全部用现有 icon 库，不新增符号）

| 分组 | icon | 设置项 |
|---|---|---|
| **观感** | 达摩 | 界面主题（分段控件：暗版 / 明版）· 底纹浓度（滑块）· 朱印强调色（4 色色板） |
| **委托** | 鸟居 | 任务类型图标（开关）· 卡片底轨进度（开关）· 全清达摩点睛（开关）· 排序方式（三选一）· 每日刷新时刻（时分输入） |
| **提示** | 铃 | 重置前提醒（关）· 可提交待领奖提醒（开） |

**注意开关的两个状态都做了**：「重置前提醒」是关（灰圆在左、底为 `--panel-2`），
「可提交待领奖提醒」是开（金圆在右、底为 `--ready-bg` + 金描边）。
两个状态同时出现在同一屏，评审时才能一眼看清两种样子的差别。

## 8 · 禁止项清单

- 禁止「方框 + 内含符号」的印章构图（铁律一）
- 禁止用增加颜色数量来提密度——密度从"面"与"纹"里补
- 器物类**只能做单色描边 icon，不得做装饰填充色块**（两者的分界在"是否有体积感"）
- 纸人 / 绘马 / 手鞠 一律不做（17px 下认不出）
- icon 描边不得细于 1.5px（小尺寸下会因抗锯齿变虚）；线条总数不超过 7 条；内部纹理不超过 2 条
- 已完成项：不得实心高饱和色块、不得发光、**不得占据右侧独立元素位**（那是倒计时与进度的领地）
- 纹样带不得比正文更显眼；底纹必须"退一步才看见"
- 卡片底轨高度不得超过 2px
- 不提供排序选项——默认按重置紧迫度降序，快过期的排最上
- 倒计时只保留一个（多倒计时造成决策瘫痪）
- 不用 emoji 当图标

## 10 · 实现陷阱（实测踩出来的，务必避开）

### 陷阱一 · `background` 简写会整个吞掉底色
```css
/* 错误 */
.task                { background: var(--card); }        /* 不透明底 */
.task[data-state=ready] { background: var(--ready-bg); }  /* 半透明叠色 → 底被替换，纹样穿透卡片 */

/* 正确 */
.task                { background-color: var(--card); }
.task[data-state=ready] {
  background-image: linear-gradient(var(--ready-bg), var(--ready-bg));
}
```
任何"在既有底色之上再叠一层半透明"的场景都要警惕这条。

### 陷阱二 · 纹样强度只能靠渲染校准
静态推演估不准。首版麻叶纹按"退一步才看见"估了暗 0.30 / 明 0.44，渲出来网格直接成了主角；
压到 **0.10 / 0.13** 并把 pattern 从 32 放大到 40 才对。**必须截图迭代，不要凭感觉定值。**

### 陷阱三 · 浅底上卡片边界会消失
明版卡片与面板的明度差必须拉开（`#E3D7C1` vs `#F5EFE3`），否则卡片看不出边界。
同时次要文字要压深（`--ink-2` 从 `#6B6255` → `#5A5245`）才够可读。

### 陷阱四 · `preserveAspectRatio="none"` 会把图案压扁
注连绳首版直接横向铺满，绳体的波浪和纸垂被压成一排方块，完全认不出。
**正确做法有二**：① 把 viewBox 的宽高比直接改成目标比例（推荐，如 `0 0 620 26` 再把路径按该画布重画）；
② 用 `slice` + 宽 viewBox 做裁切（但要算清会被裁掉多少）。
横铺类装饰**一律不要沿用图标的 24×24 viewBox**。

### 陷阱五 · 小尺寸 icon 必须"减笔画"
达摩首版在 15px 下糊成一团黑点，提灯像锯齿，折扇扇骨粘连。
根因是照搬了大尺寸下的细节密度。**17px 是本项目的 icon 下限**，
到这个尺度必须：砍掉器官细节、内部纹理 ≤2 条、线条总数 ≤7 条、描边 ≥1.5px。
可靠的做法是先按 24×24 画，再截图缩到实际尺寸看，**认不出就继续减**。

### 陷阱六 · 局部装饰的 z-index 会打架
右缘符纸装饰若 `z-index` 低于卡片，会被卡片整片盖住看不见；
高于内框又会压住框线。装饰层应设为 `z-index: 6`（在内容层 2 与内框 4 之上、外框 5 之上但 `pointer-events:none`），
并确认它落在内容区右侧的留白里（内容区 `padding-right: 30px`，符纸 `right: 16px`、宽 22px，刚好错开）。

### 陷阱七 · 切换动效绝不能用 `opacity` 做关键帧（最危险的一条）
```css
/* 危险：整页可能永久不可见 */
.tpane{display:none;animation:paneIn .3s ease}
.tpane.is-on{display:block}
@keyframes paneIn{from{opacity:0;transform:translateY(4px)}to{opacity:1;transform:none}}

/* 安全：可见性只由 display 决定，动效只做位移 */
.tpane{display:none}
.tpane.is-on{display:block;animation:paneIn .3s ease}
@keyframes paneIn{from{transform:translateY(5px)}to{transform:translateY(0)}}
```
**为什么危险**：一旦动画时间轴被冻结或动画被禁用，面板会**永久停在起始帧 `opacity:0`**——
元素在 DOM 里、`display:block`、色值全对，但用户看不见任何东西。触发条件包括：
headless 截图（`virtual-time-budget` 会冻结动画）、用户开启 `prefers-reduced-motion`、
浏览器的"减少动态效果"设置、某些扩展注入的动画拦截。

**排查手法**：用 `--dump-dom` + 在页面里把 `getComputedStyle` 的结果写进 `<title>`，
一次就能读到 `opacity` 的实际值，比盯着截图猜快得多：
```js
document.title = 'RESULT::opacity=' + getComputedStyle(pane).opacity;
```

**通用规则**：**凡是"入场动画"，永远不要把控制可见性的属性（`opacity` / `visibility` / `display`）
放进 `@keyframes`。** 可见性交给 CSS 的静态规则，动效只负责位置、缩放、旋转这类"锦上添花"的属性。
同时补一条 `@media (prefers-reduced-motion: reduce)` 的兜底。

### 陷阱八 · 小尺寸 icon 的纹理密度（专项，同陷阱五）
见 §3.5 的"17px 尺度下的简化铁律"。

### 验证工作流
```bash

```

`data-cur` / `data-total` / `data-done`，并把类型 `<svg class="ticon" viewBox="0 0 24 24"><use href="#i-xxx"/></svg>`
放在任务名前，`render()` 会自动算出状态与全部联动，无需再写任何分支逻辑。
新增一个分类 = 复制一组 `.tab` + `.tpane`（`data-tab` / `data-pane` 取同名）。
