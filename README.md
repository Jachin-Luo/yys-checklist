# 阴阳师查漏清单 · yys-checklist

一个**纯手动勾选**的阴阳师奖励自查清单。回答一个问题：

> 此刻，我还有什么奖励没拿？

**在线使用**：<https://yys.lykkk.fun>

**它不做什么**（很重要）：不登录、不读取游戏账号或游戏内数据、不模拟点击、不代打。所有完成状态都由你自己勾选 —— 它只是一张比笔记本和记忆更靠谱的清单。

## 核心思路

游戏里"漏了一次"的代价并不相等：漏一次月度黑蛋远大于漏一次每日金币。所以清单不按"游戏里有几页"组织，而按**痛感**排序 —— 越不可重复、越有截止日的条目越靠前。

痛感分由三个客观维度派生，不人工打分：

```text
痛感分 = 周期权重 + 稀缺性加成 + 固定收益加成

周期     一次性 / 限时 / 版本 / 赛季 40  >  每月 30  >  每周 20  >  每日 10
稀缺性   有 deadline 或 until          +15
固定收益 标注了 gain（具体数值）        +10
```

一键日常入口（庭院 → 事务 → 一键日常）恒排第 0 位，不参与上述比较。

## 功能

六个一级页面：**今日 / 本周 / 限时 / 统计 / 工具 / 我的**。

### 今日

- **常驻 · 活动 双 Tab**：常驻 = 长期每日模板（一键日常入口 + 每日条目）；活动 = 版本活动期才有的每日任务，活动结束自动下线，互不干扰。
- **一键日常入口卡**：官方一键日常会覆盖掉一批小任务，先点入口、再回来核对被覆盖的项。
- **重置语义是 05:00 不是 0 点**：阴阳师日常每日 05:00 重置，清单按此翻篇。页面顶部的自然日期只作展示，与勾选重置口径无关。

### 本周

- 周常 + 月常 + 版本 + 赛季条目统一收在本周视图 —— 它们的截止压力同样需要被看见，分开放只会让月常被忘掉。
- 周常周一 05:00 重置；版本 / 赛季按开服锚点重置（当前版本锚点 `2026-09-09 09:00`，赛年「寻龙逐英」锚点 `2026-07-06 06:00`）。

### 限时

- **顶部预警条**：`N 个活动在跑`，并标出其中几个将在 3 天内截止 —— 有临期项转为危险色，没有则明说"暂无临期"。
- **固定按剩余天数升序**（"哪个快过期了"是清单唯一不可替代的能力），因此这一页不给排序控件 —— 给一个点了不生效的控件只会误导。每张卡右侧标截止日与剩余天数，≤7 天转橙、≤3 天转红。
- **三个分区**：限时活动（带 deadline，参与倒计时）· **版本 / 赛季**（随周期滚动、没有 deadline，单独成区 —— 混进倒计时列表会永远垫底并稀释临期预警）· **一次性**（有 deadline 的才显示倒计时）。
- `until` 到期的条目在启动阶段就被过滤，不会赖在列表里；没标截止的（如联动、待定档）按"截止未定"处理。

### 统计

- **三个口径**：本日（每日 05:00 重置）· 本周（周一 05:00 重置）· 本月 · 版本（版本 / 赛季按开服锚点重置，活动结束清零）。
- **三条量化进度**：勾玉 / 黑碎（1 黑蛋 = 25 片）/ 蓝票，只统计标注了固定数值的条目。
- **漏失明细按痛感分级**：只列漏掉的条目名，不折算、不估算。玩家对"漏了几个黑蛋"的体感，远比"折合多少勾玉"准确。

### 工具

三段资料查询，主数据按需懒加载（合计约 180 KB，不进首屏主包；鼠标移到分段按钮上就预取）。

**御魂** —— 副本轮换与掉落

- 11 个副本按八岐系 → 永生之海 → 日轮 → 其他 → 业原火分组（分组顺序取自数据字典，改数据即可调），每组标明模式：**按星期轮换 / 跟随八岐 / 固定掉落 / 特殊产出**。
- **7 日条**：一次铺开七天掉落名单，不用来回切日期就能判断"这周值不值得刷"。
- 每张卡直接标出**二件套效果**（含首领御魂那种一整段长被动），省掉再去别处查的一步。
- 每天附加一条当日提示（哪天是招财党休息日、哪天该刷地藏像之类）。

**悬赏** —— 式神出处反查

- **全量直选**：39 个式神名单常驻，点一下就选中 —— 大部分悬赏本来就写着式神名，从列表点比先想关键词再搜快。
- **线索反查**：只有「神秘妖怪」需要按特征词查，空格分词取交集（游戏一次给两个线索）。
- **搜索不过滤名单，只做置顶 + 高亮**：匹配项前置染色，其余保持原位仅弱化，仍可点击 —— 名单是可用集合，不该被一个辅助查询收走。
- **并集区**：同时接了好几个悬赏时，能一把刷完的出处置顶高亮，一眼可判。

**结界寄养** —— 6 小时收续点

- 填上卡时间（`HH:mm`），自动排出往后每 6h 的收 / 续点（最多 5 个 ≈ 30h，够覆盖一张 6 星卡），跨天标「明天 / 后天 / 日期」。
- **任务 / 计划两态刻意的分离**：任务记状态（已过灰、下一个品牌色描边、未到绿）；计划纯查看不背状态，决定开刷时点「开始」转正。用户常常只是"打算这个点寄"，不想一存就被判成未到。

### 我的 / 设置

分区按「改动频率 × 影响面」排序，默认全部收起（每个分区摘要里带关键结论，不展开也能确认状态）。

| 分区 | 能做什么 |
| --- | --- |
| **档案** | 多账号 / 多区服档案（名称、服务器、渠道），切换、新建、归档；所有勾选与偏好按档案分片 |
| **一键日常** | 配置官方一键日常**覆盖了哪些条目**，以及被覆盖项在列表里**弱化还是隐藏** |
| **条目管理** | 新增自建条目（周期、路径、奖励类型、截止日）、隐藏预设条目、恢复默认条目库 |
| **寮时间** | 逐条配置 5 个集体活动的时间：麒麟/狩猎战、道馆突破、首领退治、狭间暗域、阴阳寮宴会×2；填好后清单里的时间徽章按你配的时刻标「未开始 / 进行中 / 已结束」 |
| **数据版本** | 看到当前条目库的数据版本与更新快照，知道自己在用哪一版 |
| **数据备份** | 导出 JSON 文本 / 粘贴导入；导入前显示档案 / 勾选记录 / 自建条目 / 已隐藏 / 自定义排序五项计数 |

几个关键设计：

- **一键日常：配置 ≠ 状态。** 单独取消某个被覆盖项的勾选，**不会**把它移出覆盖集合 —— 避免"状态变化偷偷改配置"。显示方式（弱化 / 隐藏）只影响列表渲染，**不影响**统计与漏失口径。
- **寮时间不写回主数据。** 各寮活动时间自定，写死即错；数据里的时间只是参考值，用户配置在展示层叠加。它属于"设备 / 人"的属性（换号不用重配，换手机才需要）。
- **条目管理是自定义排序的唯一入口。** 排序控件已按产品决策取消：一旦在条目管理里调过顺序，自定义顺序**直接接管**默认痛感排序（列表按周期分组展示，调序限制在组内）。
- **备份载体是文本不是文件。** 导出给一段 JSON 文本、导入收一段粘贴文本 —— 换设备时"把这段字发给自己"比"下载文件再想办法传过去"自然得多，手机上尤其明显。导出**全部档案**（只导当前档案会让另一个号悄悄丢掉）；导入是**覆盖式写操作**，必须先看摘要（档案 / 勾选记录 / 自建条目 / 已隐藏 / 自定义排序 五项计数）、再手动输入「导入」二字才可执行 —— 勾选记录是唯一无法重建的数据，误触一次的代价无法接受。导入先做结构校验 + 归一化，不合格直接拒绝；schema 版本不同只警告不拒绝（不剥夺你"试试看"的机会）。

### 全局交互

- **排序**：默认痛感分；支持 ☆ 置顶（单项星标，压过排序规则，视图条显示「已置顶 N 条」）；调过自定义顺序后由自定义接管。同分兜底依次为截止日 → 周期 → 自定义顺序。
- **筛选**：按奖励类型（高频 6 类直接做成 chip，其余收进可展开面板）+ 痛感门槛（全部 / ≥20 / ≥30，默认 0 避免冷启动整页空白）。
- **进度反馈**：各分区标题直接带计数（「今天该做 · N 项」「已完成 · N 项」「本周 · N 项未完成」）；统计页三条收益进度条。
- **刻意移除的控件**：排序选择器、隐藏已完成 —— 排序已由「默认痛感 + 置顶 + 自定义」决定，不必再让用户选；已完成分区照常展示。字段与 `isVisible` 逻辑都保留在数据层，随时可恢复。
- **布局自适应**：手机为单列 + 底部固定 Tab（带 safe-area 与 `dvh` 处理，刘海和地址栏不会压住内容）；桌面为左侧固定导航 + 多列栅格。两端共享数据层、状态层与领域逻辑，只改排列方式。
- **冷启动三步引导**：选档案 → 配置寮时间 → 开始自查（第三步由你自己决定首日要不要只看高痛感条目）。
- **可访问性**：全库统一的 `:focus-visible` 焦点环（不在组件里写 `outline-none`）、模态焦点管理、勾选卡的点击命中区域放大到整行（星标按钮 `stopPropagation`，点星不误勾）、每个图标按钮都带 `aria-label`；空态与错误态都有明确文案而不是留白。

## 口径纪律

这几条是刻意的、有单测保护的约束，改动前请先理解原因：

1. **只统计固定数值。** 浮动收益（只有类型、没有数值）不进分子分母 —— 不能把"看打掉几个"当保底算。
2. **覆盖 / 隐藏只影响渲染，绝不影响统计。** 否则"隐藏 = 少算收益"，那是数据错误而不是偏好。
3. **漏失明细只列事实、不折算、不估算。**
4. **统计忽略"隐藏已完成"。** 统计直接吃原始勾选状态，不存在"已勾条目被过滤 → 已获得归零"。
5. **时间字段只做提示、不限制勾选。** 到期条目在数据层过滤，不在渲染层判。
6. **单一数据出口。** 页面不直连种子文件，一律经 store → API 契约；`localStorage` 只由 `services/localStore.ts` 读写。

数据与代码是**双轨**的：`src/db/*.db.json` 里的枚举 code 与 `src/domain/enums.ts` 的字面量联合类型双向对齐，由 `npm run db:check` 校验，任一方向不一致即失败。

## 技术栈与架构

React 18 · TypeScript（严格模式）· Vite 5 · Tailwind CSS 3 · Zustand 5 · Vitest 2。图标 Lucide，无 UI 框架依赖。

```text
src/api/         数据契约（types / contract / index）与适配器（mock / http）
src/api/mock/    当前默认适配器：种子库 + localStorage 分片 + 故意注入的延迟与错误
src/api/http/    接后端的空壳 + TODO（端点映射已写好，本期不实现）
src/db/          条目与资料种子（items / limited / yuhun / souls / bounty / meta / users / dataVersion）
src/domain/      纯函数领域逻辑：周期、排序、痛感、统计、倒计时、合并、备份、重置、寮时间、寄养、御魂、悬赏
src/stores/      应用状态（session / items / check / view / device / ui / tools / nurture）
src/hooks/       useApi / useBootstrap / useChecklist / useAutoDaily / useBreakpoint / usePeriodRefresh / useModalFocus / useDevicePrefs / useScope
src/pages/       页面（今日 / 本周 / 限时 / 统计 / 工具 / 我的 + settings、tools 子分区）
src/components/  common（原子件）+ settings + desktop / mobile（两套布局骨架）
src/services/    用例编排（备份、剪贴板、localStorage 字节层）
tools/           数据校验（build.js）、核对报告（calibrate-report.js）、验收（verify.js）、模板
schema/          条目 JSON Schema
```

分层铁律：**页面只管排列 → store 管状态 → domain 管纯函数规则 → api 契约管数据访问。** 页面不直连种子文件，Mock 只做 IO、不含合并规则。

当前默认走**本地 Mock API**：不需要登录或后端服务，勾选与偏好存在当前浏览器 `localStorage`（按档案分片 —— 勾一条只重写该档案的状态分片，不触碰其他档案）。切换适配器靠 `VITE_API_MODE=mock|http`，`src/api/index.ts` 是唯一的选择分支。

Mock 的延迟是**故意**注入的（读 0–30ms、写 80–150ms），并且必须响应 `AbortSignal` —— 如果 mock 是瞬时的，就会写出没有 loading 态、没有竞态处理的 UI，接真实后端那天全线崩溃。

## 本地运行

需要 Node.js 18 以上（Vite 5 的要求；本项目的开发与验收在 Node 22 下跑通）。

```bash
git clone https://github.com/Jachin-Luo/yys-checklist.git
cd yys-checklist
npm ci
npm run dev
```

开发服务默认端口 `5173`，访问终端输出的实际地址。

## 开发与验收

```bash
npm test          # vitest run，单元测试
npm run lint      # eslint
npm run build     # tsc -b + vite build
npm run db:check  # 条目库校验（枚举双轨对齐、字段规格）
npm run db:calibrate   # 数据核对报告
```

一次跑完全部检查并留下可复核的验收记录：

```bash
node tools/verify.js
```

它会依次执行 `tsc -b` / `eslint` / `vitest` / `build` / 数据校验，把**当次真实输出**写进 `reports/verify-YYYY-MM-DD.md`（`reports/` 不提交仓库）。任一步失败即退出码 1，可直接接进 CI。

构建产物在 `dist/`，可用 `npm run preview` 本地预览。

### 更新条目数据的约定

游戏版本更新或活动上线时，条目 / 资料数据的录入走 `tools/templates/version-intake.md` 模板，新条目草稿写在 `tools/templates/new-items.draft.json`，校验通过后再落入 `src/db/`，并同步更新 `dataVersion.db.json` 的版本号与快照说明。

## 常见问题

**为什么不 0 点重置？**
阴阳师的日常本来就是 05:00 重置，清单跟随游戏口径。0 点翻篇会让你在凌晨 1 点看到"新的一天全部未完成"，与实际不符。

**能自动同步游戏进度吗？**
不能，这是有意的。任何形式的账号读取或模拟点击都不在项目范围内（也涉及账号安全风险），所以完成状态一律由自己勾选。

**数据存在哪？会丢吗？**
存在当前浏览器的 `localStorage`，按档案分片。换设备、换浏览器、清理站点数据都会丢，所以在换设备前请先在「我的 · 数据备份」里导出那段 JSON 文本。

**为什么统计里有些条目不算收益？**
只统计**固定数值**（勾玉 / 黑碎 / 蓝票）。数量浮动的收益不折算、不估算 —— 把"看运气掉几个"当保底算，比不算更误导。

**寮活动时间为什么不统一写死？**
各寮自定，写死即错。清单里给的是参考值，请在你自己的寮时间分区填入真实时间，之后再换号也不用重配（配置挂在设备级，不在档案上）。

## 已知限制与路线

- **纯前端单机**：数据只在本浏览器 `localStorage`，换设备 / 清站点数据前请先导出备份；HTTP Adapter 尚未实现。
- **PWA 打包暂缓**：已有图标与移动端适配（safe-area / `dvh`），但 manifest、Service Worker、安装图标尚未做，目前是普通网页而非可安装应用。
- **提醒能力已下线**（2026-09-11 整体移除）：不再有浏览器通知；相关开关与已提醒标记的存储键也已删除（旧版本残留在本机的值无人读取，无害）。
- **不做游戏数据读取**是长期定位，不是待办事项。
